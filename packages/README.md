# packages/

The four npm packages opsinjs publishes. They share one version, are MIT licensed and
ESM-only, and need Node 20.19 or newer in the project that installs them.
[ADR 0030](../decisions/0030-opsinjs-ships-as-npm-packages.md) records why opsinjs ships
this way, and [RELEASING.md](../RELEASING.md) says how a version reaches npm.

| Directory | Package | What it is |
| --- | --- | --- |
| [`react`](react/) | [`@opsinjs/react`](https://www.npmjs.com/package/@opsinjs/react) | The components, the shared substrate and the stylesheets. Most projects install only this |
| [`tokens`](tokens/) | [`@opsinjs/tokens`](https://www.npmjs.com/package/@opsinjs/tokens) | Every design token, as CSS custom properties, as JSON and as JavaScript exports |
| [`color`](color/) | [`@opsinjs/color`](https://www.npmjs.com/package/@opsinjs/color) | The colour engine: OKLCH, gamut mapping, WCAG 2 and APCA contrast, ramps and colour-vision simulation |
| [`opsinjs`](opsinjs/) | [`opsinjs`](https://www.npmjs.com/package/opsinjs) | An unscoped umbrella that re-exports the other three |

`@opsinjs/react` depends on `@opsinjs/tokens`, and `opsinjs` depends on all three.
`@opsinjs/color` has no dependencies.

## Where the source comes from

Most of each package is hand-written. Six files are generated by the scripts in
`apps/www/scripts` and must never be edited by hand:

| File | Written by | From |
| --- | --- | --- |
| `react/src/index.ts` | `build-registry.mts` | the listing of `react/src/components/` |
| `react/src/opsinjs.ts`, three marked regions only | `build-tokens.mts` | `apps/www/tokens/errors.json`, `units.json` and the banned list in `glossary.json` |
| `tokens/tokens.css`, `tokens/tokens.json`, `tokens/src/index.ts`, `tokens/src/accents.ts` | `build-tokens.mts` | `apps/www/tokens/*.json` |

Change the source and run `pnpm --filter @opsinjs/www run generate`. `pnpm check` fails
on any difference between the committed files and what the generators would write.

## Working on a package

```bash
pnpm -r --filter "./packages/*" build          # tsc per file, plus dist/styles.css for react
pnpm -r --filter "./packages/*" lint:package   # publint and Are the Types Wrong
pnpm smoke:packages                            # install the packed tarballs and use them
pnpm changeset                                 # describe the change for the changelog
```

The documentation site imports the packages through the pnpm workspace and reads their
sources directly, so `pnpm dev` needs no package build. A pull request that changes a
package carries a changeset; [CONTRIBUTING.md](../CONTRIBUTING.md) has the rest.
