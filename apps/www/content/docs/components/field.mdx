## Content guidelines

Labels are nouns in sentence case with no colon. Hints show the shape of a valid
answer, never a number a reader could read as a result. Errors say what to fix,
without blame.

<DoDont>
  <DoDont.Do>
    **"Date of birth" over three labelled fields, error "Enter a date in the past".**
  </DoDont.Do>
  <DoDont.Dont>
    **"DOB*" with "Invalid input."** An abbreviation, an unexplained symbol, no fix.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** Every colour is a role
token and no type size is in `px`. No banned word appears in a string literal,
in JSX text or an identifier.

**Argued from the source, not measured.**

- A real `label` element against a generated id, and descriptions that leave
  `aria-describedby` on unmount.
- `aria-invalid` lands on the control rather than the wrapper.
- Errors carry no colour. A glyph, the words and the left rule mark the state, a
  border forced colours keeps.
- The control reads `--opsin-target-minimum` on both axes. Nothing truncates at
  200% text.

**Not checked by any gate.** Announcing an error while focus is elsewhere, the
hint and error text roles, `forced-colors` on Windows, `autocomplete`, and
whether `children` contains a control.
