Badge is the plainest component in the system: a small neutral label attached to something else, such as a count on a tab, a short word marking a list row, or a bare number on an icon. It draws only neutral chrome and carries no meaning of its own beyond the text a caller places inside it.

The design decision that shapes the whole component is that it takes neither colour axis. A badge that could be tinted is exactly how the category axis and the status axis get mixed, because a red badge beside a StatusPill reads as a second status and a heart-tinted badge reads as a category the surface has not claimed. So Badge offers no colour prop, carries neither `data-status` nor `data-category`, and when a label has to carry a clinical level the component is [StatusPill](./status-pill.mdx) instead, which carries the colour, the icon and the word together.

The exclusion that matters is the first, and it is the reason this component was kept off the roster for so long. A badge that carries a clinical level carries it as a colour with no word and no icon, and the measured colour-vision audit in the system shows that a status told by colour alone is a status some readers cannot read at all. So the moment a label means "steady" or "needs attention", it is a [StatusPill](./status-pill.mdx) and not a Badge, and the type system cannot make that call for you because both render a short chip.

The second exclusion keeps a badge from drifting into a number display. A count of unread items is a badge; a blood pressure reading with its unit is a [Value](./value.mdx), because a Value formats the number the same way everywhere and a badge does not format anything.

Badge is a single element, so there is no part tree to nest and no composable slot to fill. What a caller controls is the content between the tags, the weight through `variant`, and how assistive technology hears the badge through `srLabel`. There is deliberately no `Badge.Icon` and no `Badge.Dot`: a coloured dot beside a count is a status told by colour alone, which is the one thing this component refuses to grow.

## Content guidelines

Keep a badge to a few characters: a number, or a short neutral word. A badge is a label attached to something else, so it names or counts and then stops, and long content in a pill wraps into a lozenge nobody can read at a glance. Give a bare number a noun through `srLabel` so a screen-reader user hears what it counts, and set `srLabel` to an empty string only when the count is already spoken in full beside the badge.

Never write a clinical status word into a badge. "Steady" and "Needs attention" belong in a [StatusPill](./status-pill.mdx), where the word sits beside the colour and the glyph that let a reader who cannot use the colour still read the level. A status word in a neutral chip is a level told without its carriers, which is precisely the mistake the two axes are kept apart to prevent.

## Accessibility

Some of this is enforced by a gate on every pull request and every push to `main`, and the rest is argued and labelled as such. At `alpha`, accessibility is claimed only where it has been checked, with the gaps listed rather than left out. Nothing here has been through a review with a disabled user.

**Checked, by `pnpm run check:a11y`:**

- **No status colour, no colour literal, no ramp step.** The badge draws only the neutral chrome roles, so it carries no `data-status`, reads no clinical vocabulary, and cannot mix the two axes. The gate reads every element and would fail the build on a colour drawn from either axis or on a raw colour value, and there is neither here.
- **No px type size.** The chip's text is the `caption1` semantic step rather than a pixel size, so a reader who has turned their text size up gets a larger badge instead of a pinned one.

**Argued, and true of the implementation, but not yet measured:**

- **A decorative badge can be removed from the accessibility tree.** Setting `srLabel` to an empty string marks the badge `aria-hidden`, so a count that is already spoken beside it is not read twice. A count that stands alone is named instead, so it is never a lone number with no noun.
- **The badge is not interactive.** Nothing takes focus, answers a key or a pointer, or animates, so there is no keyboard contract to honour and no motion for `prefers-reduced-motion` to reduce.
- **At 200% text the chip grows with the text.** The pill is sized from the type step and its padding is in space tokens, so the whole badge scales rather than clipping its content.

**Not checked at all, and listed rather than omitted:**

- Every contrast pair: the muted ink against the muted fill in the soft weight, and the neutral hairline against the host ground in the outline weight. `scripts/check-contrast.mts` has not been run for this component, which is why the report below is empty rather than reassuring.
- What the chip draws under `forced-colors: active`, where the fill and the hairline are both replaced by the platform's own pair. None of this has been put in front of a machine or a high contrast user.

## API reference

<PropsTable name="BadgeProps" />

`variant` chooses between two neutral weights and nothing else: there is no colour prop, because a badge is on neither the category axis nor the status axis. `srLabel` is how a caller names a bare count for a screen reader or hides a decorative one, and it is the only accessibility affordance the component needs, because a badge has no state and no behaviour. `children` is the visible content, and keeping it to a few characters is a content rule the type cannot enforce.

## Related

<RelatedComponents name="badge" />

**Easily confused with**

- [StatusPill](./status-pill.mdx) is the component for a label that carries a clinical level. It draws the colour, the icon and the word together, so the level survives greyscale and colour-vision deficiency, which a neutral badge cannot do.
- [Value](./value.mdx) formats a measurement and its unit the same way everywhere in the product. A badge counts or names; it formats nothing.
- [Callout](./callout.mdx) sets a short piece of information apart in a block. A badge is a chip attached inline to something else, not a block of its own.

**Used by**

- No pattern, recipe or screen composes it yet. It is a neutral primitive that a product attaches to its own tabs, list rows and headings.
