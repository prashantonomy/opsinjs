```tsx

```

```tsx

  <ul>
    {items.map((item) => (
      <li key={item.id}>{item.label}</li>
    ))}
  </ul>
</ScrollArea>
```

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.**

- No status colour, no colour literal, no ramp step. The region draws only
  neutral chrome and carries no `data-status`.
- No `px` type size and no oversized radius, so the chrome scales with the text.

**Argued from the source, not measured.**

- Base UI gives the viewport `overflow: scroll` and a tab stop when there is
  more to see, so a keyboard reader reaches it.
- Nothing traps focus. The viewport is one ordinary tab stop, and its focus ring
  shows which region the reader entered.
- `overscroll-contain` hands the scroll back to the page at the region's end, so
  a reader is never stuck inside it.
- A rem-based `maxHeight` grows with the reader's text; a pixel-based one clips.

**Not checked by any gate.** The thumb's contrast, what the rail draws under
`forced-colors: active`, and whether the fade-in leaves a switch user a handle to
aim at.

## API reference

<PropsTable name="ScrollAreaProps" />

`maxHeight` gives the region something to overflow, so set it in a rem rather
than a pixel count. Given neither it nor a height class, the region grows to fit
and a development warning names the omission. `className` is the one route by
which colour reaches the region, and the two-colour-axes rule applies in full.
