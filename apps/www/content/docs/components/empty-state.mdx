Empty states are where a product either explains itself or looks broken. In a health product
there is a fifth thing they must not do: imply that empty means fine.

The first exclusion is the one that produces the worst experience when it goes wrong. An
empty state shown during loading tells the reader there is nothing there, and a proportion of
them will leave before the data arrives and conclude the app lost their readings.

## Anatomy

<Anatomy name="empty-state" />

<CompositionTree name="empty-state" />

**Illustration** is optional and never carries information. **Title** says what is not here.
**Body** says why, in one or two sentences. **Action** is the one thing to do next; there is
one, not three. **Secondary** is an optional quieter route for the reader who cannot take the
primary one.

Proposed part hierarchy. This is the specification the implementation must match.

```text
EmptyState                     root; declares WHY it is empty
├── EmptyState.Illustration    optional; decorative, hidden from assistive technology
├── EmptyState.Title           what is not here
├── EmptyState.Body            why, in 1–2 sentences
├── EmptyState.Action          the one next step
└── EmptyState.Secondary       optional quieter alternative
```

## Proposed API

```ts
// PROPOSED. Not implemented. A specification for review, not an API to generate
// code against. It will change without a deprecation cycle.

/**
 * Why the surface is empty. Required, because each reason needs different words
 * and one of them is a safety statement rather than an inconvenience.
 */
export type EmptyReason =
  /** The reader has not added anything yet. */
  | "nothing-yet"
  /** A filter or search matched nothing. The data exists. */
  | "no-matches"
  /** There was content and there is none now — everything completed or removed. */
  | "nothing-left"
  /** There is data, but not enough for this view to be honest. */
  | "not-enough"

export interface EmptyStateProps {
  reason: EmptyReason
  title: string
  children?: React.ReactNode
  /** Exactly one primary action, or none. Never a row of three. */
  action?: { label: string; href?: string; onSelect?: () => void }
  secondary?: { label: string; href?: string; onSelect?: () => void }
  /** Decorative only. Never the carrier of the message. */
  illustration?: React.ReactNode
}
```

## Content guidelines

Say what is not here, then why, then what to do. Never use an empty state to be cheerful about
an absence: *No results — great news!* is a clinical claim the product cannot make, because a
reader with no results has an empty list, not a clean bill of health.

For `not-enough`, state the rule and the gap. The reader is not being told off; they are being
told what the view is waiting for.

<DoDont>
  <DoDont.Do>
    **"No readings yet. Once you add your first blood pressure reading, you will see it here
    along with your range. [Add a reading]"** Names the absence, says what will change it,
    offers one action.
  </DoDont.Do>
  <DoDont.Dont>
    **"Nothing to see here! 🎉"** Cheerful about missing health data, no explanation, and
    nothing to do. It reads as reassurance and it is not reassurance about anything.
  </DoDont.Dont>
</DoDont>

<DoDont>
  <DoDont.Do>
    **"Not enough readings for a trend yet. We show one after 7 days of readings — you have
    3."** The rule, the gap, and no implication that the reader has done anything wrong.
  </DoDont.Do>
  <DoDont.Dont>
    **An empty chart area with the axes drawn.** It looks like a failure, and readers who
    interpret it as *your values are zero* are not being unreasonable.
  </DoDont.Dont>
</DoDont>

## Accessibility requirements

Requirements for the implementation, not results.

- **The empty state replaces the content in the reading order** and its title is a real
  heading at the level the surrounding page needs, so it is findable rather than stumbled
  into.
- **A view that becomes empty announces it politely** — after a filter change, for example —
  once, and not on every keystroke.
- **The illustration is decorative** and hidden from assistive technology. If a picture is
  carrying meaning, the meaning is missing from the words.
- **The action is a real button or link** with a 44pt target and a name that says what it
  does.
- **Nothing depends on colour**: the state is carried by the words.
- **At 200% text the layout stacks** and the illustration shrinks or disappears before the
  text does.
- **Print** renders the title and body; an empty section in a printed summary must still say
  why it is empty, or the reader will think the print failed.
