## Usage

```tsx
import { SegmentedControl } from "@/components/ui/segmented-control"
```

```tsx
<SegmentedControl
  label="Chart window"
  value={chartWindow}
  onValueChange={setChartWindow}
  options={[
    { value: "day", label: "Day" },
    { value: "week", label: "Week" },
    { value: "month", label: "Month" },
  ]}
/>
```

## Content guidelines

Keep the labels short, parallel and in sentence case, one or two words each, so
the row reads as siblings. Name the value the option sets, not an
instruction, and give it no terminal punctuation. Order them the way the reader
thinks, shortest to longest, and keep one wording across screens.

<DoDont>
  <DoDont.Do>
    **"Day" · "Week" · "Month"** Three parallel windows, one word each, ordered
    shortest to longest.
  </DoDont.Do>
  <DoDont.Dont>
    **"Today" · "This week's readings" · "Show me the month"** Three lengths and
    three grammars, so the row stops reading as one set.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** Every colour is a role
token and no type size is in `px`.

**Argued from the source, not measured.**

- A radio group, so the row is one tab stop with a roving focus rather than one
  stop per option.
- `label` is required and applied as the group's `aria-label`. A missing one
  raises a development warning rather than rendering an unnamed group.
- Selection is carried three ways: `aria-checked`, the card surface lifting the
  segment off the track, and a hairline.
- The focus ring sits in the segment's own classes, and each segment floors its
  target at `--opsin-target-minimum` in rem.

**Not checked by any gate.** No contrast pair measured, no screen reader run,
Home and End unbound, and no `forced-colors` or `prefers-contrast: more` rule.

## API reference

<PropsTable name="SegmentedControlProps" />

`value` and `onValueChange` make this controlled, with no internal selection
state. A `value` matching no option renders the row with nothing chosen and
raises a development warning. `label` is required, because a radiogroup with no
accessible name is a defect the type system cannot otherwise prevent.
