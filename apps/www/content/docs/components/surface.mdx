## Accessibility

The audit found zero axe violations, no target-size or focus-visible finding and
no horizontal scroll at 320px, and changed nothing. The surface is
presentational, with no role, name or tab stop, and its three decorative layers
are empty and `aria-hidden`. The Backdrop renders only where the Scrim is
unconditional, so no text sits over an unscrimmed blur. Reduced
transparency, `prefers-contrast: more`, `forced-colors: active` and a missing
`backdrop-filter` each reach a defined
[opaque fallback](../foundations/accessibility.mdx) that keeps the border,
shadow and geometry. The boundary is an outline, so `forced-colors` preserves it
where a shadow would be dropped.

**Residual items.** Both belong to the token owner, not to this file.

- Under `prefers-contrast: more` the edge [widens](../foundations/accessibility.mdx) from a hairline to an emphasis width but keeps its published `--opsin-material-*-border` colour, and several rungs publish a low alpha, so whether it clears 3:1 for SC 1.4.11 is unmeasured. A solid colour would give `canvas` and `scrim` an edge they are specified not to have, so the fix sits in `tokens/material.json`.
- `className` is merged unrestricted, so a caller can put a category tint and a status tint on one Surface, which the component cannot detect at render time. The [two colour axes](../health/two-colour-axes.mdx) rule and its repair are stated on the API, and no element the component itself renders mixes them.

## Props interface

<PropsTable name="SurfaceProps" />

`rung` is required, because no default depth is safe to guess. There is no
`blur`, `opacity`, `tint`, radius or `as` prop, and no `contentWeight`, because
no large-text scrim floor has been measured. A rung outside the six is refused.
Development warns and the children still render, with no material. `className`
is merged unrestricted, so the [two colour axes](../health/two-colour-axes.mdx)
rule applies in full.
