## Content guidelines

Name the setting the switch turns on, not its state: *Larger text*, never *On* or
*Turn on larger text*. Sentence case, a few words, no full stop. The helper line
says what the setting does; it never repeats the label or carries a reading, a
threshold or a unit.

<DoDont>
  <DoDont.Do>
    **"Larger text"** names the setting and stays true whichever way the switch is flipped.
  </DoDont.Do>
  <DoDont.Dont>
    **"I agree"** records consent, which belongs in a [ConsentSheet](./consent-sheet.mdx).
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** Only neutral chrome and the
bridged primary fill, so no status colour or colour literal, no type size in `px`,
and no banned word.

**Argued from the source, not measured.**

- The root is a label element, so words and track are one pressable region
  floored at `--opsin-target-minimum` in rem.
- `aria-checked` reflects the caller's boolean, the thumb sits left for off and
  right for on, and a hairline survives a stripped fill.
- The label and helper are type steps, so the row grows with the reader's text size.
- The role, the single tab stop and the Space and Enter bindings come from
  Base UI's Switch.

**Not checked by any gate.** Every contrast pair, the 44 by 44 target in a real
browser, `forced-colors: active`, `prefers-contrast: more`, right-to-left thumb
travel, and `prefers-reduced-motion`, which the slide and the fade do not honour.

## API reference

<PropsTable name="SwitchProps" />

`checked` and `onCheckedChange` make this a controlled component with no internal
state. `label` is required: a missing or empty label raises a development warning.
`disabled` keeps the switch visible and labelled while refusing focus and every
key. `className` is merged onto the root row and must carry neither colour axis.
