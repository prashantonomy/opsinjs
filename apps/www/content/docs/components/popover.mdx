<ComponentInstall

```tsx
import { Popover } from "@/components/ui/popover"
```

```tsx
<Popover title="How readings are grouped" trigger="Why two lists?">
  <p>
    Entries you add yourself sit in one list, and entries from a connected
    device sit in another, so you can always tell which is which.
  </p>
</Popover>
```

## Accessibility

The panel is `role="dialog"`, named by `aria-labelledby`, and a missing title warns.
Base UI moves focus into the panel on open and back to the trigger on close. The arrow
is `aria-hidden`, and under `prefers-reduced-motion` only opacity crossfades. The
component uses only neutral chrome, the `overlay` shadow token and the `body` and
`headline` steps, with no status colour, literal, ramp step or `px` size. The trigger's
hit area was floored on height alone, so an icon-only trigger could clear the AA 24px
minimum while still missing the house width floor. The audit added a matching `min-w`
at `--opsin-target-minimum`, following the `icon-button` pattern, so the width is
floored too.

**Residual items.**

- The wrapper takes no `aria-label` prop, so an icon-only trigger needs a name from the
  caller's trigger node. Every shipped trigger already uses named text.
- Contrast pairs remain unmeasured, below.

## Props interface

<PropsTable name="PopoverProps" />

`trigger` is the button's visible content; a button here would nest inside another.
`side` defaults to `bottom`, a preference the primitive overrides on collision.
`className` merges onto the panel and must resolve neither colour axis.
