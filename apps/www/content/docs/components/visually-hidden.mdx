## Accessibility

Content is announced because the span is clipped, not `display:none`,
`visibility:hidden` or the `hidden` attribute, each of which removes content from the
tree. The clip was checked against the WebAIM sr-only reference and stays hidden
through 200% text and increased text spacing, because neither touches its overflow and
clip-path. It
paints nothing and sets no colour or type size, so there is nothing to reflow at 200%
text, and as text rather than a control it is never focusable or a tab stop. Axe,
target size, focus visibility and reflow at 320px raised nothing.

The audit added a development-only warning when a focusable control sits inside the
always hidden clip, a keyboard trap with no visible focus ring. The component walks
its children to find one, and the warning changes no markup, class or visual output.

**Residual items.**

- No gate checks whether VoiceOver, NVDA, JAWS and TalkBack announce the content.
- Whether hidden text duplicates a visible name beside it is a per-usage question the
  component cannot see, so it stays a concern for the caller.

## Props interface

<PropsTable name="VisuallyHiddenProps" />

`children` is required. Empty children, an empty string, `undefined` or `false` raise
a development warning naming the mistake, and the span still renders. `className`
reaches the span for positioning, and a class that makes the content visible defeats
the component.
