## Usage

```tsx
import { Tabs } from "@/components/ui/tabs"
```

```tsx
<Tabs
  label="Reading detail"
  value={panel}
  onValueChange={setPanel}
  items={[
    { value: "overview", label: "Overview", panel: <Overview /> },
    { value: "history", label: "History", panel: <History /> },
    { value: "notes", label: "Notes", panel: <Notes /> },
  ]}
/>
```

## Content guidelines

Keep tab labels short, parallel and in sentence case: one or two words, the same
part of speech, no terminal punctuation. Do not use tabs to hide content a reader
needs together, such as a side by side comparison.

<DoDont>
  <DoDont.Do>
    **"Overview" · "History" · "Notes"** name what each tab reveals, in one grammar.
  </DoDont.Do>
  <DoDont.Dont>
    **"Overview" · "Click for the full history"** mixes grammars, and one label instructs.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** The row draws neutral
chrome with no colour literal and no ramp step. No `px` type size, and each tab
floors its target at `--opsin-target-minimum`.

**Argued from the source, not measured.**

- Base UI's Tabs renders the WAI-ARIA pattern: a tablist of tabs, each with
  `aria-selected`, controlling a tabpanel.
- Activation is manual. Arrow keys move the highlight and Enter or Space commits.
- Three sighted carriers plus `aria-selected` mark the active tab, so the
  selection survives greyscale.
- The focus ring sits in the component's own classes, not the product
  stylesheet.

**Not checked by any gate.** Every contrast pair for the active ink, the rail
and the indicator bar, plus `forced-colors: active` and `prefers-contrast: more`.

## API reference

<PropsTable name="TabsProps" />

`value` and `onValueChange` make this controlled, with no internal selection
state. A `value` matching no item renders no active tab and warns in
development. `items` holds each tab's value, label and panel together.
