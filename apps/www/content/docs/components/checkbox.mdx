## Accessibility

The description is tied with `aria-describedby`, and fill, border and the Check against
Minus glyph move together, so colour is never the sole state carrier. Sizes are rem,
and the colour transition moves no transform, so it needs no reduced-motion guard. The
audit
fixed a missing name (WCAG 4.1.2): Base UI draws the box as a `span` with
`role="checkbox"`, and the wrapping `label` named only the hidden input. The box now
points `aria-labelledby` at the visible label's `id`, so its name is the visible words
verbatim (WCAG 2.5.3), in the demo and both examples.

**Residual items.**

- The inner box measures 20 by 20, under SC 2.5.8, but the pointer target is the 44px
  label row, which toggles anywhere along it and so clears the house floor.
- Contrast pairs are not yet measured.

## Props interface

<PropsTable name="CheckboxProps" />

`label` is required. `checked`
accepts `true`, `false` or `"indeterminate"`; omitted, the box is uncontrolled
from an unticked start. `indeterminate` is the other route to the mixed state
and wins when both are given. `onCheckedChange` reports a boolean, so a mixed
box reports `true` when ticked.
