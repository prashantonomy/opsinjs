A sparkline is a claim that a pattern exists. Four points and a slope look exactly like
forty points and a slope, and the reader cannot tell them apart. Most of this specification
is about refusing to draw a line that the data does not support.

The third exclusion is the one products get wrong. A sparkline is a glyph, not a chart: no
axes, no gridlines, no hover. The moment a reader needs to know *which* day the spike was,
the component has failed and a real chart belongs there instead — see
[Chart anatomy](../foundations/data-visualisation/chart-anatomy.mdx).

## Clinical meaning

**What it asserts.** That these readings, of this measurement, in this unit, were recorded
at these times, and that the line joins them. It asserts the shape of a series and nothing
about its cause.

**What it must never be read as.** A prediction, an explanation, or a verdict. A line
sloping upward does not mean the reader is getting worse, and a line sloping downward does
not mean they are getting better — the valence depends entirely on the measurement, and for
several common measurements it depends on the person. The component therefore states
**direction** (up, down, level, unsettled) and leaves valence to whatever the product
chooses to say beside it, as
[Trends and change](../health/trends-and-change.mdx) requires.

**Which colour axis it may use.** The **category** axis, on the line itself, because a
sparkline's job in a dashboard is to be findable among five others and the category tint is
what makes the heart series distinguishable from the sleep series. The **status** axis may
appear only on a single emphasised point where the product has assigned a status to that
reading — never as the colour of the whole line. A line that changes colour along its length
to show good and bad regions is the two-axis collision in its purest form; see
[The two colour axes](../health/two-colour-axes.mdx).

**Who owns the window and the minimum.** The product. TrendSparkline has no default window,
no default minimum point count, and no smoothing. It renders what it is given, and refuses
to render a line when it is given less than the product said was enough.

**Gaps are data.** Missing readings are drawn as breaks, never bridged by interpolation, and
the caption says how many are missing. A continuous line over a fortnight of absent data is
a claim the product cannot support — see
[Uncertainty, staleness and missing data](../health/uncertainty-and-staleness.mdx).

<SafetyCallout severity="medium" evidence="opinion">
The y-axis is never truncated to make a change look larger. Health measurements have
meaningful zero-distance and clinically meaningless variation, and a zoomed axis converts
ordinary noise into an apparent event. If the change is too small to see on an honest axis,
the honest answer is that there is nothing to see.
</SafetyCallout>

## Anatomy

<Anatomy name="trend-sparkline" />

<CompositionTree name="trend-sparkline" />

**Line** is the series. **Band** is the optional shaded reference range behind it, drawn in
neutral tones so that in-range and out-of-range are visible without becoming a verdict.
**Point** is an emphasised reading — usually the latest, occasionally one the product has
flagged. **Caption** is the sentence that carries the whole component when the graphic is
unavailable, and it is mandatory. **Window** states the period, because a line with no
period is unreadable.

Proposed part hierarchy. This is the specification the implementation must match.

```text
TrendSparkline                 root; owns series, window, minimum point count
├── TrendSparkline.Plot
│   ├── TrendSparkline.Band    optional reference range behind the line; neutral only
│   ├── TrendSparkline.Line    the series; category-tinted, broken across gaps
│   └── TrendSparkline.Point   an emphasised reading; may carry status
├── TrendSparkline.Caption     direction, magnitude, window, gaps — mandatory
└── TrendSparkline.Window      the period covered, e.g. "last 14 days"
```

Never place a `TrendSparkline.Point` on an interpolated position. If the reading does not
exist, the point does not exist.

## Proposed API

<NotBuiltYet name="trend-sparkline" />

```ts
// PROPOSED. Not implemented. A specification for review, not an API to generate
// code against. It will change without a deprecation cycle.

import type { ClinicalStatus, HealthCategory, ReferenceRange } from "opsinjs"

export interface TrendPoint {
  /** ISO timestamp of the reading. */
  at: string
  /** `null` records a known gap. Gaps are drawn as breaks, never bridged. */
  value: number | null
  /** Status for this reading only. Never colours the line. */
  status?: ClinicalStatus
}

/** Direction is a fact about the series. Valence is a judgement, and not ours. */
export type TrendDirection = "up" | "down" | "level" | "unsettled"

export interface TrendSparklineProps {
  label: string
  unit: string
  /** Chronological. Gaps are explicit `null` entries, not omissions. */
  series: TrendPoint[]
  /**
   * The minimum number of real readings before a line may be drawn. Supplied by
   * the product; below it the component renders its not-enough-data state.
   */
  minimumPoints: number
  /** The period the series covers, stated to the reader. */
  window: string
  /** Drawn behind the line in neutral tones. Never status-coloured. */
  range?: ReferenceRange
  /** Tints the line so it is findable in a grid. */
  category?: HealthCategory
  /**
   * The caption. When omitted the component composes one from direction,
   * magnitude, window and gap count — and never from valence.
   */
  caption?: string
}
```

## Content guidelines

Captions state direction, magnitude, window and gaps, in that order, and stop. Leave the
interpretation to the product's own copy in the surrounding
[CareCard](./care-card.mdx) or paragraph, where it can be attributed to somebody.

Avoid *improving*, *worsening*, *better*, *worse*, *on track* and *off track* inside the
component. They are all valence, and valence in a caption is a verdict nobody signed.

<DoDont>
  <DoDont.Do>
    **"Down about 4 bpm over the last 14 days. 2 days have no reading."** Direction,
    magnitude, window, gaps. A reader can check every word of it against the picture.
  </DoDont.Do>
  <DoDont.Dont>
    **"Trending in the right direction. Keep it up."** Valence with no author, praise for
    something the reader may not have caused, and no way to tell how much changed or over
    how long.
  </DoDont.Dont>
</DoDont>

<DoDont>
  <DoDont.Do>
    **"Not enough readings yet. We show a trend once you have 7 days of data — you have 3."**
    Names the rule, names the gap, gives the reader something to do.
  </DoDont.Do>
  <DoDont.Dont>
    **A line through three points.** It looks exactly like a trend and it is not one, and
    nothing on screen distinguishes them.
  </DoDont.Dont>
</DoDont>

## Accessibility requirements

Requirements for the implementation, not results.

- **Every sparkline ships a text twin.** The caption is in the accessibility tree and states
  direction, magnitude, window and gaps. A reader who cannot see the line loses the picture,
  not the information. See
  [Accessible charts](../foundations/data-visualisation/accessible-charts.mdx).
- **A data-table twin is available** for any sparkline whose underlying readings the reader
  may need — reachable from the same surface, not a separate page.
- **The graphic is `role="img"` with the caption as its name**, not focusable, not
  announced point by point. A fourteen-point series read aloud one point at a time is worse
  than silence.
- **The line is distinguishable from the band without colour**, by weight and by the break
  pattern across gaps, and survives the generated CVD audit.
- **Category tint never encodes meaning**, so grayscale loses nothing but findability.
- **At 200% text the caption reflows** to as many lines as it needs and the plot shrinks in
  height rather than the caption truncating.
- **Motion is not used to draw the line in.** A path that animates its own length implies
  progress and reads as time passing; under `prefers-reduced-motion` there is nothing to
  degrade because there was nothing there.
- **Print** renders the line as a solid stroke, the band as an outline, gaps as visible
  breaks, and the caption as text.
