## Content guidelines

Labels are short, parallel and in sentence case, naming the value each option sets.
Order them the way the reader thinks, and keep an option's wording the same on
every screen. Add a description only when the label cannot stand alone.

<DoDont>
  <DoDont.Do>
    **"Standard" · "Quiet" · "None"** are parallel single words, ordered from most
    to least, so they read as siblings.
  </DoDont.Do>
  <DoDont.Dont>
    **"Standard reminders" · "Keep it quiet" · "I want nothing"** are three
    grammars, so they stop reading as one set.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.**

- Every colour is a neutral chrome role or the primary ink.
- No type size is in `px`.

**Argued from the source, not measured.**

- One roving tab stop: `role="radiogroup"` on the root, `role="radio"` and
  `aria-checked` per option. Selection follows focus.
- `label` is required, rendered as a visible legend and wired by `aria-labelledby`.
  An empty one warns in development.
- Selection is carried three ways: `aria-checked`, the lifted ring, the filled dot.
- Each row floors its hit area at `--opsin-target-minimum` in rem, with its own
  focus ring.

**Not checked by any gate.** Every contrast pair, the drawing under
`forced-colors: active`, and how a screen reader reads a description.

## API reference

<PropsTable name="RadioGroupProps" />

`value` and `onValueChange` make this a controlled component with no internal state.
A `value` matching no option renders nothing chosen and raises a development
warning. A disabled option stays in the list, drawn in the muted ink and skipped
by the Arrow keys. No options renders nothing.
