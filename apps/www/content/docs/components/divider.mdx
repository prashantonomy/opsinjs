## Examples

<ComponentPreview name="divider" />

### A labelled boundary in a list

`label` marks the seam between today's items and the earlier ones. The two lists
carry the grouping on their own; the divider is the visible echo, not the only signal.

### A vertical rule between inline facts

`orientation="vertical"` draws a hairline that takes its height from the flex row
around it. In a block that gives it no height it collapses to nothing.

## Accessibility

The audit changed nothing. The divider is not focusable and captures no key, in either
orientation, labelled or not. Unlabelled, the root exposes `role="separator"` with
`aria-orientation`, so a reader navigating by region can skip it. Labelled, the root
has no role, because a separator cannot carry an accessible name, and the label is
plain text between two `aria-hidden` hairlines. Every colour is a role token, no type
size is in `px`, and no banned word appears.

**Residual items.**

- A divider is never the only carrier of grouping for a screen reader, so the groups
  either side must be separated by structure too.
- The hairline's contrast against a card, a sheet and the page, and the labelled
  form's footnote text against `--muted-foreground`, are not yet measured. Both are
  shared role token pairs missing from the generated contrast table, so fixing either
  means editing the token set, outside this component's own file.

## Props interface

<PropsTable name="DividerProps" />

`orientation` defaults to `horizontal`; an unknown value is drawn horizontal with
a development warning. `label` applies to the horizontal form only and is dropped
with a warning on a vertical rule. A whitespace-only label counts as none.
`className` is the only route by which colour can reach the component, and both
colour axes stay off it.
