## Content guidelines

Keep labels short, parallel and in sentence case, with no terminal punctuation,
and name what happens from the reader's side. Order them the way the reader
moves, because list order is draw order. Write a description only when the label
leaves a real question open.

<DoDont>
  <DoDont.Do>
    **"Your details" then "Your preferences" then "Review"** reads as one set.

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** Every colour is a role
token, no type size is in `px`, and no banned word appears anywhere.

**Argued from the source, not measured.**

- The root is an `<ol>` and each step an `<li>`, so a screen reader announces a
  list of known length and reads it in order.
- The current step carries `aria-current="step"`, the signal for the reader's
  position within a set.
- State is never colour alone. Each step carries an sr-only "Completed",
  "Current step" or "Upcoming" beside its shape.
- The check glyph is `aria-hidden`, and the indicator holds no tab stop because
  it is read-only and has nothing to operate.

**Not checked by any gate.** No contrast pair is measured and nobody has
listened to this in a screen reader. There is no `forced-colors` or
`prefers-contrast: more` rule.

## API reference

<PropsTable name="StepperProps" />

`current` is a 0-based index into `steps`, so the product owns the position and
the component keeps no state of its own. A value outside the range, or a
non-integer, is truncated and clamped to the nearest real step and raises a
development warning.
