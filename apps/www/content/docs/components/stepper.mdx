## Accessibility

The root is an `<ol>` with `<li>` steps, so a screen reader announces a list of
known length, in order, and the current step carries `aria-current="step"`. State
never rests on colour alone: glyph, fill weight, border weight, label weight,
list position, and an sr-only "Completed", "Current step" or "Upcoming" all carry
it. The check glyph is `aria-hidden`, and the indicator takes no tab stop, since
it has nothing to operate. The audit fixed the root list's missing accessible
name: an optional `label` now forwards to the root `<ol>` as `aria-label`, set on
the default and both examples. When it is omitted, the attribute is dropped
rather than shipping empty.

**Residual items.**

- The upcoming marker's hairline border against the page is an unmeasured contrast pair. Meaning does not rest on it, because number, position, the sr-only word and label weight already carry upcoming state.
- No live region announces a change of `current`. The parent flow owns focus and announces each new page, so `aria-live` would fire on unrelated renders.
- A consumer who omits `label` ships an unnamed list. The default and both examples set it, the recommended usage.

## Props interface

<PropsTable name="StepperProps" />

`current` is a 0-based index into `steps`; the product owns position, the
component keeps no state of its own. An out-of-range or non-integer value is
clamped to the nearest real step and raises a development warning.
