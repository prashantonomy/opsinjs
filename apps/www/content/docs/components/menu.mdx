## Usage

```tsx
import { Menu } from "@/components/ui/menu"
```

```tsx
<Menu
  trigger={<button type="button">Actions</button>}
  items={[
    { label: "Share", onClick: onShare },
    { label: "Rename", onClick: onRename },
    { label: "Remove from list", separatorBefore: true, onClick: onRemove },
  ]}
/>
```

## Content guidelines

Name each action as an imperative, *Rename* rather than *Renaming*, common
ones first. A destructive action carries its object, *Remove from list* rather
than *Remove*, because no tint marks it.

<DoDont>
  <DoDont.Do>
    **"Share" · "Rename" · "Remove from list"** names the destructive action
    with its object.
  </DoDont.Do>
  <DoDont.Dont>
    **A red "Delete" item** borrows the status axis and destroys on a single
    press.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.** Only neutral chrome
roles, no colour literal, no `px` type size, and every item floored at
`--opsin-target-minimum`.

**Argued from the source, not measured.**

- Base UI renders `aria-haspopup`, `role="menu"` and `role="menuitem"` on the
  trigger, popup and items.
- The highlight is the neutral `state-hover` surface, so it survives greyscale.
- A disabled row drops to the muted ink rather than an opacity wash.
- Escape and a choice both return focus to the trigger.

**Not checked by any gate.** Every contrast pair, the popup under
`forced-colors: active` and `prefers-contrast: more`, and how a screen reader
speaks a separated group.

## API reference

<PropsTable name="MenuProps" />

`trigger` must be a single focusable element. No items, one item, or an
enabled item with no `onClick` each raise a development warning. `className` is
merged last onto the popup and must carry no status or category tint.
