Select is a trigger that opens a list to choose one option from. Its home is a single choice out of a list too long to lay out flat, a timezone or a unit system being the case it was built for, where the options are worth having but not worth the vertical space of showing them all at once.

The design decision that shapes the whole component is that it trades the glance of a flat set for the compactness of a closed trigger. A [RadioGroup](./radio-group.mdx) or a [SegmentedControl](./segmented-control.mdx) shows every option at once and is the better answer while the options are few; a select earns its place only once the list grows past what a row can hold, because it keeps a long list from pushing the rest of a form down the page. It sets a value and nothing more, so it carries neither colour axis and draws only neutral chrome.

The control is built on Base UI's Select primitive, which is where the single tab stop on the trigger, the listbox keyboard and the portalled popup come from, so installing it pulls in `@base-ui/react`. It draws two glyphs, the open indicator and the selected tick, from `lucide-react`.

## Usage

```tsx
import { Select } from "@/components/ui/select"
```

```tsx
<Select
  label="Timezone"
  placeholder="Choose a timezone"
  value={timezone}
  onValueChange={setTimezone}
  options={[
    { value: "lisbon", label: "Lisbon" },
    { value: "berlin", label: "Berlin" },
    { value: "tokyo", label: "Tokyo" },
  ]}
/>
```

The exclusion that matters is the first, and it is a question about how many options there are. Under roughly seven options a flat set is easier to scan than a list behind a trigger, so a [RadioGroup](./radio-group.mdx) that shows every option at once is the better control, and reaching for a select there hides a short list nobody needed to hide. A select earns its place only once the list is long enough that laying it flat would cost more space than it is worth.

The second exclusion keeps a select off a clinical value. A select chooses a plain option and formats nothing; a blood pressure band or a symptom scale is a measurement with a range and a meaning, and that is a [ReadingInput](./reading-input.mdx), which formats the number the same way everywhere and leaves the verdict to the consuming product rather than to a bare dropdown.

The parts above are identified by `data-slot` and are styleable from outside; none of them is an export, and there is no way to render an item outside the popup or the popup outside the root. The item's text sits in a `Select.ItemText` carrying `data-slot="select-item-text"`, which Base UI also reads for its type-to-find, and it is named here rather than left for someone to find in the DOM. There is no colour prop and no status slot: the selection is the tick and `aria-selected`, not a tint, because a select is on neither axis.

## Content guidelines

Keep the option labels short, parallel and in sentence case, and name the value each option sets rather than an instruction to the reader. Order them the way the reader thinks about them rather than the way the data is stored: a list of frequencies runs shortest to longest, and reversing it to match a database column is the list nobody can scan. Do not change a label's wording between screens for the same option, because a reader who learnt that this control offers "Once a week" should not meet "Weekly" meaning the same thing elsewhere.

Write the placeholder as a prompt, not as an option. "Choose a timezone" tells the reader what to do; a placeholder that reads like a real value, such as a plausible timezone, is a trap, because a reader cannot tell whether it is a default they have accepted or a blank they still have to fill. When one option is the sensible starting point, set it as the value instead of leaving the trigger empty, so the reader begins with a real choice rather than a prompt dressed as one.

## Accessibility

Some of this is enforced by a gate on every pull request and every push to `main`, and the rest is argued and labelled as such. At `alpha`, accessibility is claimed only where it has been checked, with the gaps listed rather than left out. Nothing here has been through a review with a disabled user.

**Checked, by `pnpm run check:a11y`:**

- **No status colour, no colour literal, no ramp step.** The control draws only the neutral chrome roles, so it carries no `data-status`, reads no clinical vocabulary, and cannot mix the two axes. The gate reads every element and would fail the build on a colour drawn from either axis or on a raw colour value, and there is neither here.
- **No px type size, no oversized radius.** The trigger and the options use the `body` semantic step rather than a pixel size, and the popup uses `rounded-opsin-lg` rather than an off-ramp radius, so a reader who has turned their text size up gets a larger control instead of a pinned one.
- **A 44pt target floor.** The trigger and each option floor their hit area at `--opsin-target-minimum` in rem, so the pressable region survives and grows with the reader's text size rather than pinning at a device pixel.

**Argued, and true of the implementation, but not yet measured:**

- **The trigger is one tab stop with the WAI-ARIA listbox keyboard.** Base UI renders the trigger as a combobox, the popup as a listbox and each option as a `role="option"` with `aria-selected`, and the open, move and choose sequence follows the pattern rather than a bespoke one. Whether it reads cleanly to a screen reader has not been heard.
- **The trigger has an accessible name.** `label` is required and applied as the trigger's `aria-label`, so a screen-reader user hears what the control chooses before its value; a missing or empty `label` raises a development warning rather than rendering an unnamed control.
- **The selection is not told by colour alone.** The chosen option carries a Check glyph and `aria-selected`, and the placeholder is the measured muted ink switched on by `data-placeholder` rather than a faded value, so both survive greyscale.
- **The focus ring is carried in the trigger's own class list.** A project installed without the product stylesheet keeps the ring rather than losing it silently.

**Not checked at all, and listed rather than omitted:**

- Every contrast pair: the foreground ink on the background surface at the trigger, the foreground ink on the card surface in the popup, the muted placeholder ink, and the hairline against each ground. `scripts/check-contrast.mts` has not been run for this component, which is why the report below is empty rather than reassuring.
- What the popup draws under `forced-colors: active`, where its material shadow and both surfaces are replaced by the platform's own pair, and there is no `prefers-contrast: more` rule. None of this has been put in front of a machine or a high contrast user, and the primitive's own type-to-find has not been checked against a screen reader's type-to-find.

## API reference

<PropsTable name="SelectProps" />

`value` and `onValueChange` make this a controlled component with no internal selection state: the caller stores the chosen value and passes it back, and a value left empty or matching no option shows the placeholder. `label` is required, because a combobox with no accessible name is a defect the type system cannot otherwise prevent, and `placeholder` is a prompt shown on the empty trigger rather than an option that can be chosen. `options` is the list, each a value, a visible label and an optional `disabled` flag; keeping the labels short and parallel is a content rule the type cannot enforce.

**Easily confused with**

- [RadioGroup](./radio-group.mdx) shows every option at once and is the better control under about seven options, where a flat set is easier to scan than a list behind a trigger. A select earns its place only once the list is long enough to be worth folding away.
- [SegmentedControl](./segmented-control.mdx) sets a parameter of one view from a small set of options laid out flat on a single row. A select is for a longer list and a choice the reader opens rather than sees.
- [ReadingInput](./reading-input.mdx) is the control for a clinical value with a range and a meaning. A select chooses a plain option and formats nothing.
