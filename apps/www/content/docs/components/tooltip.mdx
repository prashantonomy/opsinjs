## Examples

### On an icon button

Each icon button carries its own name through `aria-label`, and `content` repeats
it visibly for a pointer or keyboard reader. The labels name fictional actions,
never a reading.

### A supplementary hint

The setting is named in plain words on the surface, so a touch reader needs no

## Content guidelines

Keep a tooltip to a phrase, in sentence case, with no terminal punctuation unless
it is a full sentence. Write what the control does or what the value means, never
an instruction that only appears on hover.

<DoDont>
  <DoDont.Do>
    **"Reminders wait until the morning during the hours you set here"** beside a
    setting already labelled on the surface.
  </DoDont.Do>
  <DoDont.Dont>
    **The only label on an icon-only control, shown on hover alone.** A touch
    reader sees a bare glyph.
  </DoDont.Dont>
</DoDont>

## Accessibility

**Checked by `pnpm run check:a11y` on every commit.**

- No status colour, no colour literal and no ramp step, so the component sits on
  neither colour axis.
- No `px` type size: the label is the `footnote` step.

**Argued from the source, not measured.**

- Base UI wires the popup through `aria-describedby`, so the label is a
  description announced after the control's own name, never a replacement.
- Focus opens the tooltip, Escape dismisses it, and focus never leaves the
  trigger.
- At 200% text the popup grows with the label, capped at the tight measure so it
  wraps rather than clips.

**Not checked by any gate.** Every contrast pair, and what the popup and arrow
draw under `forced-colors: active` and `prefers-contrast: more` on each side.

## API reference

<PropsTable name="TooltipProps" />

`content` is required; an empty one raises a development warning. `children`
must be focusable, so a bare span gets no tooltip on the keyboard. `side` defaults
to `top` and Base UI flips it at the screen edge. `delay` defaults to 600 and
governs the pointer only; focus opens the tooltip at once.
