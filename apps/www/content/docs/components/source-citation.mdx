## Clinical meaning

**Asserts.** Where a health value came from, in the product's own plain words, with an optional checked date and a link to the fuller source.

**Never read as.** A guarantee that the source is right, current, or checked by anybody. `checkedOn` is the date the product recorded, and a value old enough to doubt is wrapped in [RelativeTime](./relative-time.mdx) beside it.

**Colour axis.** Neither: no `status` prop and no `category` prop, and a class from either axis raises a development warning. See [Two colour axes](../health/two-colour-axes.mdx).

**Thresholds.** None. No reference range, verdict or clinical number passes through, and the product owns the words. Of the ten provenance rules in [Trends and uncertainty](../health/trends.mdx), rules 22 to 31, this component carries two, provenance in plain words at the value (rule 23) and a manufacturer's claim attributed rather than restated (rule 27). The other eight stay the caller's, and it renders a wrong string as readily as a right one. opsinjs ships no source, date, DOI or study. See [Safety review](../health/safety-review.mdx).

<SafetyCallout severity="attention" evidence="opinion">
Never restate a manufacturer's accuracy figure as your own, and never invent one. Attribute the claim and link it through `more`, in the manufacturer's own terms.
</SafetyCallout>

## Accessibility

The audit found no axe violation, missed target size, hidden focus or loss at 320px reflow. Both lines are set at `text-opsin-footnote`, a rem from the generated ramp and never a `px` size, in `--foreground` for the source and `--muted-foreground` for the date, with no raw colour literal or ramp step. `more` carries the label and the href together, so a link cannot be added without a label, and an external href adds an off-screen "opens in a new tab". The link is not inside a sentence, so it re-adds `--opsin-target-minimum` on both axes. See [Accessibility](../foundations/accessibility.mdx). It reflows at 200% text with no fixed height, and `min-w-0` with `wrap-break-word` breaks a long device name.

**Residual items.**

- The source line, the last-checked time and the fuller-citation link render as loose siblings with no programmatic group binding them. Reading order keeps the association, so this is not an AA failure.
- The "Last checked on" chrome is always English while the date follows the caller's `locale`, and when they differ the localised date carries no `lang` seam yet, per ADR 0005.

## Props interface

<PropsTable name="SourceCitationProps" />

`source` is typed optional but required by the contract, so the missing state can render. `checkedOn` is a strict `YYYY-MM-DD` string or epoch milliseconds, both pinned to UTC. A value that is not a real calendar date is refused, not rendered as a plausible wrong one.
