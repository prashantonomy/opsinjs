## Accessibility

Only neutral chrome roles reach the box, never a status colour, literal or ramp step,
and its type is the `body` step, not a pixel size. The focus ring rides in the box's own
classes, so it survives without the product stylesheet, and the height floors at the
house target. There is no axe, target-size, focus-visible or 320px reflow failure.

**Residual items.**

- The box needs an accessible name and invents none. A Field label, an `aria-label` alone
  or an `id` with a real `<label htmlFor>` gives it one, and with none of `aria-label`,
  `id` or `name` a development warning names the gap.
- A persistent visible label is recommended, not required, and the default export uses
  one.
- `invalid` sets `aria-invalid` and leaves the border neutral, because a form error is
  not a clinical status. [Field](./field.mdx) places the message, so a standalone box
  cannot associate an external message id.
- `maxLength` is forwarded with no visible counter or live remaining-count region, so
  pair the limit with a visible count near the box, as the Content guidelines say.
- Disabled state is a muted fill, not an opacity wash, so the text stays legible, and
  WCAG exempts disabled controls from the contrast floor.
- No gate checks contrast, or the box under `forced-colors: active` and
  `prefers-contrast: more`, including the browser's resize handle.

## Props interface

<PropsTable name="TextareaProps" />

`value` with `onChange` makes the box controlled, and `defaultValue` leaves it
uncontrolled. `rows` sets the resting height and defaults to three. `className` is
merged last and must resolve no `--opsin-status-*` or `--opsin-category-*` role.
