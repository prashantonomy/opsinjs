Install one package, load one stylesheet and render a component. Paths below are for Next.js, and the table at the end lists what differs elsewhere. [Packages](./packages.mdx) says what each package holds.

## Prerequisites

- React 19 or later. React 18 is not supported.
- Node 20.19 or later. The packages are ESM-only.
- Tailwind CSS v4, but only if your app already uses Tailwind. There is no v3 path.
- Control over stylesheet order.

## Install

```npm
npm install @opsinjs/react
```

It brings `@opsinjs/tokens`, Base UI, `lucide-react`, `clsx` and `tailwind-merge` with it. Nothing is written into your source tree, and an upgrade is `npm update` plus the [changelog](./changelog.mdx).

## Choose a stylesheet

Load exactly one of these two, once, at the root of the app.

**Without Tailwind**, import the precompiled stylesheet. It holds the tokens, the role layer and only the utilities the components use. It has no preflight, so it never resets the rest of the page, and its utilities sit in cascade layers, so your own unlayered CSS wins.

```tsx title="app/layout.tsx"
import "@opsinjs/react/styles.css"
```

**With Tailwind CSS v4**, import opsinjs after Tailwind in the stylesheet Tailwind compiles. That loads the tokens, the role layer and the theme bridge, and points Tailwind at the compiled components with `@source`. The opsinjs utilities, such as `text-opsin-headline`, `bg-background` and `rounded-opsin-*`, then work in your own code too.

```css title="app/globals.css"
@import "tailwindcss";
@import "@opsinjs/react/tailwind.css";

/* Your own overrides last, so they win. */
```

## Base styles

`@opsinjs/react/base.css` is optional, with either stylesheet. It sets the html font, the body background and ink, the border role on every element, the selection wash, the focus ring, tabular figures on `[data-opsinjs-value]`, and a 2.75rem target floor on buttons, inputs, selects and textareas. It is opt-in because it reaches every element on the page, not only opsinjs ones.

```tsx title="app/layout.tsx"
import "@opsinjs/react/styles.css"
import "@opsinjs/react/base.css"
```

With Tailwind, add `@import "@opsinjs/react/base.css";` after the opsinjs import instead.

## Dark mode and accent

Dark mode is the `dark` class on an ancestor, usually `<html>`. The accent theme and the accent are attributes, and they theme everything inside the element that carries them. Set both on the same element.

```html
<html class="dark" data-accent-theme="vibes" data-accent="volt">
```

| Attribute | Values | Default |
| --- | --- | --- |
| `data-accent-theme` | `normal`, `vibes`, `stryk` | `normal` |
| `data-accent` | `cobalt`, `sky`, `jade`, `volt`, `rose`, `orchid`, `violet`, `iris`, `graphite` | `cobalt` |
| `data-density` | `compact` | Unset |

[Accent](./foundations/accent.mdx) explains the themes, and [Theming](./theming.mdx) covers the tokens behind them.

## Render a component

```tsx title="app/page.tsx"
import { StatusPill } from "@opsinjs/react"

export default function Page() {
  return <StatusPill status="watch" describes="Blood pressure" />
}
```

`status` is required, because your product assigns it and opsinjs never derives one. `describes` is what a screen reader announces the level as being about. [StatusPill](./components/status-pill.mdx) has the full contract.

Check that the pill is styled, that its background reads an `--opsin-status-*` custom property, and that in greyscale it still names its level in words and by icon.

## Other frameworks

| Setup | What differs |
| --- | --- |
| [Next.js](./nextjs.mdx) App Router | The reference install |
| Vite | Client only. Import the stylesheet once, at the entry point |
| React Router framework mode | Load the stylesheet from the root route, through `links` for a CSS file, so error routes get it too. Upgrade Remix to React Router 7 first |
| TanStack Start | Vite rules apply. Load the stylesheet in the root route's document shell |
| Astro | Import the stylesheet from your layout. Display components need no hydration directive. An interactive component must share an island with its trigger |
| Monorepo | List `@opsinjs/react` in the `package.json` of every app that renders it, and load a stylesheet in each |

No row has a recorded end-to-end test, and the TanStack Start and Astro rows come from each framework's architecture, not from a build. Create React App and React Native are not targeted, and there is no Vue or Svelte build, though `@opsinjs/tokens` is plain CSS and works anywhere.

## Browser support

The floor opsinjs commits to testing is Safari and iOS Safari 16.4, plus the current and previous major versions of Chrome, Edge and Firefox. Backdrop blur, `corner-shape`, Display P3 colour and `linear()` springs are enhancements. They degrade to an opaque surface, circular corners, the sRGB value the contrast floor is measured against, and the browser's default easing.

## Troubleshooting

**`@opsinjs/react` does not resolve.** It is ESM-only and needs Node 20.19 or later. In a monorepo, it must be listed in the app that imports it.

**The component renders unstyled.** No opsinjs stylesheet is loaded. Import `styles.css` at the root, or import `tailwind.css` in the stylesheet Tailwind compiles.

**An opsinjs utility such as `text-opsin-headline` does nothing in your own markup.** `styles.css` holds only the utilities the components use, so read the custom property with `var()` instead, or move to the Tailwind setup. With Tailwind, the opsinjs import must sit in the stylesheet Tailwind compiles, after `@import "tailwindcss"`.

**Utilities appear twice.** Both `styles.css` and `tailwind.css` are loaded. Keep one.

**Colours are wrong or empty.** Your own CSS sets a role such as `--primary` to a literal, or it reads a primitive token that no theme reaches. See [Theming](./theming.mdx).

**The accent does not change.** `data-accent-theme` and `data-accent` sit on different elements, and they do not combine across elements. Put both on one.

**There is no focus ring and the page font is the browser's.** `base.css` is not loaded. Import it, or style those yourself.
