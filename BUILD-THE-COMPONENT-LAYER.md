## 0. Eight decisions that block everything. Make them before you spawn a single agent.

Each of these is a contradiction between two things the repo already asserts. None of them has an answer on disk. Every one of them will otherwise be answered differently by 24 different implementers, or will stop Phase 2 dead. Write each into **one substrate contract file** that is injected verbatim into every implementer agent, and record the load-bearing ones as ADRs (numbered from 0009).

**0-A. The zero-props contradiction — this blocks Phase 2 on day one.** `app/(view)/view/[base]/[style]/[kind]/[name]/page.tsx` does `(await entry.component()).default` and renders `<Preview />` **with no props**. But `StatusPillProps.status` is documented "Required. There is no neutral default and no 'unknown' level", and the same file's text is what `shadcn add` installs as `files[].content`. The default export therefore cannot be the component. **Resolution: every registry file has two exports.** A named export that is the real component with its real required props (`export function StatusPill(props: StatusPillProps)`), and `export default` — a zero-prop demo that renders the named component with representative props. `/view` and every screenshot render the default; a consumer imports the named one. This also determines what `<ComponentSource>` displays and what `shadcn add` hands a consumer, so it goes in the substrate contract before anything is written.

**0-B. Shared code cannot reach a consumer, so Phase 2's "check that cannot be faked" is unpassable until you fix the emitter.** A component importing `@/lib/status` or `@/lib/utils` compiles in `apps/www` (`tsconfig.json` sets `paths: {"@/*": ["./*"]}`) and **fails in a throwaway app** unless the file ships too. `scripts/build-registry.mts` line 308 hardcodes both halves: `` path: `registry/${item.specifier.slice(2)}.tsx` `` and `type: "registry:ui"`. A `.ts` lib file gets a wrong extension *and* a wrong type. Derive both from the source file (`.ts` → `registry:lib`, `.tsx` → `registry:ui`) and ship the shared substrate as its own registry item that every component names in `registryDependencies`. `shadcn init` gives a consumer `lib/utils.ts`, so `cn` is safe to import; nothing else is.

**0-C. Where shared code physically lives — 0.6's own warning is the trap.** `findBuilt()` registers **every** direct-child `.ts`/`.tsx` under `registry/bases/<base>/` as a component, with no catalogue row required. Dropping `types.ts` or `warn.ts` there silently creates `REGISTRY_INDEX["base/base-lyra/component/types"]`, a live `/view/base/base-lyra/component/types` route, and an entry no catalogue row backs. `lib/` is not scanned and therefore cannot ship. Pick one and name it in the contract: `registry/bases/base/<name>.ts` **with** a catalogue row, or `lib/opsinjs/` plus an explicit copy step into the registry. Do not drop an unregistered helper into `registry/bases/base/`.

**0-D. Are the anatomy parts a public API? This is the single largest source of 24 divergent components.** Every spec's `## Anatomy` names parts as `ResultCard.Header`, `RangeBar.Track`, `StatusPill.Icon` and calls the tree "the specification the implementation must match" — while `status-pill.mdx` line 117 says the pill "is deliberately not composable". Decide once. **Default: internal structure identified by `data-slot`**, exporting a real dot-notation compound part *only* where a spec has the consumer slot content in (`Card.Header`, `Sheet.Content`, `Field.Control`). Record it as an ADR, because `<CompositionTree>`, `<DataAttributesTable>` and `<CssVariablesTable>` at `beta` all document whichever answer you pick.

**0-E. The data-attribute vocabulary.** The repo mandates `data-status` and `[data-opsinjs-value]` and nothing else, yet the `beta` outline requires a `## Data attributes` section read off the implementation. Freeze four: every part carries `data-slot="<component>-<part>"` (shadcn's convention, kebab-case); every status-bearing element additionally carries `data-status`; every rendered measurement carries `data-opsinjs-value` (already the convention — see `components/docs/health.tsx:325` and `foundations/typography/type-scale.mdx:62`); category-tinted elements carry `data-category`. A fifth attribute requires a contract edit first.

**0-F. Example demo data collides head-on with the never-invent rule.** `ReferenceRange.source` is required, OPSIN-0004 fires on a `range` with no `rangeSource`, `<ComponentPreview>` needs a rendered RangeBar, and §7 forbids shipping a reference range or inventing a citation. An implementer will write `source: "NHS"` and that is a fabricated citation in a health system. **Every example and every zero-prop default export uses obviously-synthetic data with an explicit non-source** — put the exact literal in the contract so all 24 use one string, e.g. `source: "Example data — not a reference range"` — values that are not plausible clinical readings wherever the spec allows it, and never a named laboratory, guideline body or device manufacturer.

**0-G. The a11y rig cannot measure what Phase 1 asks it to measure.** Hit area, 1.3× and 200% reflow all need a layout engine; §7 bans `playwright` from every `package.json`; there is no test runner, no `test` script in either package.json and no `test` task in `turbo.json`. **Split the rig in two.** A static gate — a new `scripts/check-a11y.mts`, plain Node 24, no new dependency — enforces what is checkable from source: colour + icon + word + `data-status` on every status surface, no `px` font size, no raw colour literal, no element resolving both `--opsin-category-*` and `--opsin-status-*`, banned words in copy and identifiers. Wire that into `.github/workflows/ci.yml`. Layout-dependent checks go into `.github/workflows/nightly.yml`, which is **already the only place Playwright is installed** (`pnpm --filter @opsinjs/www add --save-dev playwright` at job time, never committed to a manifest). Fix `capture-registry.mts` (0.7) first — it is the existing browser harness.

**0-H. Git strategy.** Branch off `main` as `feat/component-layer`. One commit per phase item and one per component, each carrying its regenerated artefacts. Do not push and do not tag.

## 2. Orchestration: Workflow + ultracode

Use the **Workflow** tool with **ultracode**. Design your own scripts; respect this decomposition, which follows the real dependency graph:

- **Phase 0 parallelises well** — its items are file-disjoint: the outline enforcer (`scripts/assert-ia.mts`), the registry payload (`app/_machine/*`, `scripts/build-registry.mts`), the docs-side seams (`components/docs/*`), the theme bridge (`app/product.css`), the material emitter (`scripts/build-tokens.mts`). No implementer commits a generated file.** One integrator per batch runs `generate` once, reads the 38-file diff, runs the gate set, and commits.
- Inject the single substrate contract file from §0 into every implementer agent rather than restating it per-agent.

## 4. Contracts

**Registry.** Flat `.tsx` files at `apps/www/registry/bases/base/<catalogue-id>.tsx`; the filename stem is the catalogue `name`, the docs URL segment and the registry item name — one id everywhere, no mapping table. Every file has `export default` rendering with **zero required props** (the `/view` route does `(await entry.component()).default` and renders `<Preview />` with no props) plus the named real component from 0-A. Examples at `registry/examples/<component>-<variation>.tsx`; screens at `registry/screens/<screen-id>.tsx`; neither has catalogue rows nor appears in any `/r` payload. `registryDependencies` compose by bare name, never inline a copy. Props interfaces are named exports `<Component>Props` declared with `export interface` — never an inline object type, never `ComponentProps<typeof Base.Root>`.

**Never hand-edit a generated file:** `apps/www/lib/generated/**`, `apps/www/registry/__index__.ts`, `apps/www/registry/generated/**`, `apps/www/app/tokens.generated.css`, `apps/www/content/docs/reference/generated/**`, `apps/www/content/docs/reference/api/**`, `apps/www/public/r/**`, and any `content/docs/components/<id>.mdx` carrying the line `Generator: scripts/build-registry.mts`. Change the source, run `generate`, commit the output in the same commit.

**Styling.** Semantic tokens only: `--opsin-{category|status}-{name}-{surface|line|ink|accent}` and named material rungs. Never a ramp step (`--opsin-category-heart-600`), never a raw colour literal (hex, `rgb()`, `hsl()`, named colour, Tailwind arbitrary colour). **The `/view` palette is smaller than the docs chrome palette** — `--secondary`, `--accent`, `--destructive`, `--sidebar*`, `--chart-1..5` and `--radius-2xl/3xl/4xl` exist only in `app/globals.css`, so `bg-accent` or `bg-destructive` looks fine under the docs chrome and renders unstyled at `/view`. Note the axis asymmetry in `product.css`'s `@theme inline`: `--color-status-<level>` maps to `--opsin-status-<level>-**line**`, while `--color-category-<name>` maps to `--opsin-category-<name>-**accent**`. So `bg-status-urgent` is the line role and `bg-category-heart` is the accent role. `accent` is a fill chosen for recognition, not contrast — never text on it, never a sole boundary. No `px` sizes: type is one of the eleven semantic steps (`--opsin-text-{large-title,title1,title2,title3,headline,body,callout,subheadline,footnote,caption1,caption2}-*`), spacing is `--opsin-space-*` (the half-step is `--opsin-space-0-5`, hyphen not dot), icons beside text size in `em`. Every rendered measurement carries `data-opsinjs-value`. Pair a spring easing with its own duration; `spring-calm` for anything displaying a health value.

**Clinical.** One element takes colour from exactly one axis; both on one screen is correct, both on one surface is OPSIN-0001 (`safety`) — call `axisConflict()`. Status renders colour **and** a lucide icon **and** the word, plus `data-status`; per `status-pill.mdx:208` that means four distinct glyph *shapes*, not one glyph in four colours. `tokens/color.json:1241` carries a measured CVD audit — `lib/color/cvd.ts` run over the four status accents under protanopia, deuteranopia, tritanopia and greyscale — finding that `steady` and `attention` are identical (Lc 0) under deuteranopia and greyscale, and `steady` and `urgent` identical under tritanopia. The word is the primary carrier, not reassurance. `unknown` is the absence of an assertion, not a fifth level (OPSIN-0011) — keep the type split between `ClinicalStatus` and `ClinicalStatusOrUnknown`; the CSS namespace will not save you. The six health categories are `sleep`, `heart`, `activity`, `nutrition`, `mind`, `labs` — there is no seventh and there is no `cycle`. Status is always an input, never derived from a value, a bar position or a trend direction. `null` is a first-class state distinct from `0`: an explicit absence with a words-based accessible label, never `0`, never a bare dash. Never animate a health value on first paint — no count-up, no dial sweep, no progressive reveal. Never mount a live region on the caller's behalf; value changes polite, only `urgent` assertive via `role="alert"` on `AlertBanner`. A component never moves focus on appearance; focus is trapped only in modal surfaces, always returns to the trigger, positive `tabindex` banned, a composite widget is one tab stop. Never use a banned word in copy, default labels **or code identifiers** — `normal` is banned outright (no `normalRange`, no `isNormal()`); lint against the **union** of the generated `BANNED_WORDS` (10 entries: `abnormal`, `bad`, `diagnosis`, `don't worry`, `failed`, `just`, `negative`, `normal`, `poor`, `positive`) and the table at `content/docs/health/reference-ranges.mdx:48-54`, which adds `healthy`/`unhealthy`, `good`, `perfect`/`optimal` and `elevated`. The two lists differ; the union is the rule.

**MDX and IA.** The vocabulary is **closed** — **77** tags in `MDX_VOCABULARY` in `scripts/assert-ia.mts` (lines 175–264) plus five child tags in `MDX_CHILD_TAGS` (`Step`, `Tab`, `Accordion`, `File`, `Folder`). A new tag means: anatomy contract, then `components/mdx.tsx`, then `MDX_VOCABULARY`, then the template, then a page. `PlannedApi` and `CategoryGrid` are in the vocabulary but deliberately **unregistered** in `components/mdx.tsx` (comment at line 124) — a page using them passes `check:ia` then renders undefined. The frontmatter schema is `additionalProperties: false`: a new key goes in **both** `content/_templates/frontmatter.schema.json` and `source.config.ts`. Never write a literal `"/docs…"` in `app/**`, `components/**` or `lib/**` — build paths through `apps/www/lib/routes.ts` (`viewPath()`, `ViewKind`, `componentPath()`); in MDX use relative file links. Never start a component page from another component's page.

**The alias gate is a superset warning, not an exact match.** `registry/catalogue.ts`'s header comment (line 18) claims `assert-ia.mts` "fails the build when a page's `aliases` are not exactly its catalogue row's". The actual rule is `CAT006` (assert-ia.mts:1611), a **warning**, and it only reports catalogue aliases the page is *missing*. `content/docs/components/status-pill.mdx` already carries three aliases (`badge`, `chip`, `tag`) its catalogue row does not, and the build is green. Do not assume they are in sync; the file's own comment is wrong about its enforcement.

**Scripts** under `apps/www/scripts/` stay `.mts` run by plain Node 24 type stripping: erasable syntax only (no `enum`, no parameter properties, no `namespace`), relative imports with explicit `.ts` extensions. `tsconfig.json`'s `include` covers `**/*.mts`, so they are typechecked under `strict: true` from `tsconfig.base.json`. `registry/catalogue.ts`, `lib/status.ts`, `lib/catalogue.ts` and `lib/routes.ts` must stay free of JSX for the same reason. `eslint.config.mjs` ignores only `.next/**`, `out/**`, `build/**`, `next-env.d.ts`, `.source/**`, `lib/generated/**`, `registry/__index__.ts` and `public/r/**` — so `registry/bases/**` is both linted and typechecked.

## 7. Hard prohibitions

- **Never weaken a gate to get green.** Making an enforcer *correct* (0.1) is required work; making it *lenient* is forbidden. No allowlist entry, no relaxed policy, no deleted assertion to turn a red green. Adding a gate is always allowed.
- **Never invent a citation, statistic, DOI, date, study or measurement.** No hand-written contrast ratio, bundle size, prop row, token row, keyboard row or data attribute. Prefer `evidence: opinion` to a plausible-looking reference. `<NoDataYet>` is the correct output when the generator has no data.
- **Never ship a reference range, threshold, plausibility bound, score band, staleness default, emergency number, or default disclaimer text** — for any metric, in any population, ever. An omitted one renders an explicit "we do not have this" state, never a substituted default. A `range` with no `rangeSource` is OPSIN-0004 (`safety`). This applies to example data too — see 0-F.
- **Never encode clinical status by colour alone**, and never carry status, urgency or meaning through motion, sound or haptics.
- **Never create `apps/www/app/layout.tsx`.** The two sibling root layouts — `app/(chrome)/layout.tsx` (globals.css, lyra) and `app/(view)/layout.tsx` (product.css only) — are the entire preview isolation mechanism; ADR 0007 exists for this.
- **Never claim a component works without a passing preview you have looked at.** "It typechecks" is not "it renders": `<ComponentPreview>` renders `<NotBuiltYet>` regardless of whether the file compiles.
- **Never mark a page `stable`.** Stable requires a measured accessibility bar, measured contrast pairs, a generated bundle cost, and having shipped in a real product. `alpha` and `beta` are the honest ceilings for this session.
- **Never add** `culori`, `apca-w3`, `@radix-ui/*`, `next-themes`, `motion`, `@tailwindcss/typography`, `tsx`/`ts-node`, or `playwright` to any `package.json`. Never float a pinned version (the manifest pins exact versions for everything but `prettier` and its Tailwind plugin). Never add a `webpack` key to `next.config.mjs`. Never write `/r/*.json` files into `public/r/` — a static file there beats the route handler.
- **Never assert a diagnosis, cause or prognosis, and never tell a reader a result is nothing to worry about.**
